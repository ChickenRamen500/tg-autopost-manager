# Шаг 0 — my.telegram.org/apps: получение api_id / api_hash

Документ решает типовую проблему: при создании приложения форма возвращает
**«ERROR» без конкретики**. Ниже — разбор причин и гарантированно рабочая конфигурация.

---

## Гарантированно рабочая конфигурация полей

| Поле | Значение | Комментарий |
|---|---|---|
| **App title** | `TG Autopost Manager` | Без дефисов/подчёркиваний, только буквы + пробелы. Дефис в заголовке — частая скрытая причина ERROR. |
| **Short name** | *(оставить пустым)* | Это поле нужно **только для платформ iOS/Android/uwp** (URL-схема deep-link). Для Web его не заполняют. Заполнение Short name при выбранной платформе Web может давать ERROR. |
| **Platform** | **Web** | Мы используем Bot API через aiogram на сервере — это «обычный» MTProto-клиент, платформа Web подходит. |
| **URL** | *(оставить пустым)* | Необязательно для Web. Если хотите заполнить — только полный URL с протоколом: `https://example.com`. Домен без протокола (`example.com`) или с пробелами → ERROR. |
| **Description** | `Local media queue bot for Telegram (self-hosted Bot API server)` | Латиница, без спецсимволов. Можно пусто. |

### ⚠️ Про выбор платформы в ТЗ
В §3.3 ТЗ указан флаг `--local` у **локального Bot API сервера** — это отдельная
история (Docker-контейнер tdlib), к выбору платформы на my.telegram.org отношения не имеет.
Платформу в форме выбирайте **Web**, а не «Other»: «Other» иногда требует пояснения
в Description и капризничает с валидацией.

## Полный чек-лист, если ERROR повторяется

1. **App title**: длина 1–… символов, только `[A-Za-z0-9 ]`, без `-`, `_`, `.`, эмодзи, кириллицы.
   - ❌ `tg-autopost-manager` → ✅ `TG Autopost Manager`
2. **Short name**: только латиница+цифры, 5–32 символа, **или пусто**.
   - Проверьте, что не вставилось с пробелом на конце/начале (особенно при копировании).
3. **URL**: пусто, либо валидный абсолютный URL (`https://...`).
4. **Нет лишних пробелов** ни в одном поле (частая причина при paste).
5. **Сессия авторизации не протухла**: страница `/apps` живёт столько, сколько cookie;
   если сидите давно — залогиньтесь заново (выйти → войти).
6. **Номер телефона вводите в международном формате** при логине: `+7XXXXXXXXXX` / `+380XXXXXXXXX`.
7. **Браузер/расширения**: uBlock/AdGuard иногда ломают форму (блокируют скрипт отправки).
   Отключите или попробуйте режим инкогнито / другой браузер.
8. **Не отправляйте форму дважды подряд** — после ошибки подождите 10–15 секунд
   (защита от флуда отвечает тем же голым ERROR).
9. **Проверено на аккаунте с включённой 2FA?** Иногда мешает — но обычно нет;
   если ничего из вышеперечисленного не помогло, попробуйте временного отключить облачный пароль.
10. **Альтернатива без веб-формы**: получить api_id/api_hash можно прямо из Telegram —
    откройте официальный бот-помощник или используйте клиент, где виден `api_id`
    (например, через `t.me/API`-подобные сервисы не рекомендуем; надёжнее —
    повторить попытку в другом браузере).

## После успешного создания

Страница покажет:
```
ApiId: 1234567        ← целое число
ApiHash: 0a1b2c...    ← 32 hex-символа
```

Перенесите в `.env`:
```env
TELEGRAM_API_ID=1234567
TELEGRAM_API_HASH=0a1b2c...
```

Далее по PHASE1_GUIDE.md:
```bash
docker compose up -d local-bot-api
python scripts/check_phase1.py --logout
python scripts/check_phase1.py --health
python scripts/check_phase1.py --big-test
```

## Быстрая диагностика docker/local-bot-api (если доберётесь)

```bash
# живой ли сервер
curl -s http://localhost:8081/health ; echo

# getMe через локальный сервер
curl -s "http://localhost:8081/bot<TOKEN>/getMe"
# error_code 401 → ещё не сделали logOut с облака (check_phase1.py --logout)
```
